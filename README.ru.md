# Постановка языка · Mandarin tongue placement diagram

*[Read in English](README.md)*

Интерактивная схема сагиттального разреза рта: показывает, куда ставится язык
для инициалей (согласных) и финалей путунхуа. Доступна на русском (`ru.html`)
и английском (`en.html`). Написано на TypeScript.

## Структура репозитория

```
index.html              → редирект на ru.html (для корня GitHub Pages)
ru.html                 → русская версия (тонкая HTML-обёртка)
en.html                 → английская версия (тонкая HTML-обёртка)
assets/
  style.css              → общие стили (одинаковые для обоих языков)
src/
  types.ts               → общие типы: Point, SoundGroup, AppData и т.д.
  geometry.ts             → чистые функции геометрии языка/нёба (без DOM)
  engine.ts               → рендер + анимация; принимает AppData параметром, без текста внутри
  data.ru.ts               → весь русский текст + координаты звуков, типизировано как AppData
  data.en.ts               → то же самое на английском
  main.ru.ts / main.en.ts   → точки входа, просто вызывают mount(data)
tests/
  unit/
    geometry.test.mjs       → тесты геометрии (node --test, без браузера)
    data.test.mjs            → тесты согласованности данных ru/en
  e2e/
    app.spec.ts               → Playwright: реальный браузер, оба языка, все звуки
dist/                     → скомпилированный JS (собирается из src/, в git не хранится)
.github/workflows/
  lint.yml                 → typecheck + ESLint + html-validate на каждый push/PR
  test.yml                  → unit + e2e тесты на каждый push/PR
  deploy.yml                 → сборка + unit-тесты + деплой на GitHub Pages при пуше в main
tsconfig.json               → конфиг сборки src/
tsconfig.tests.json          → отдельный конфиг для типизации tests/e2e
playwright.config.ts
eslint.config.js
.htmlvalidate.json
package.json
CONTRIBUTING.md
LICENSE
```

`engine.ts` не содержит ни слова текста — всё лежит в `data.ru.ts` / `data.en.ts`
и типизировано интерфейсом `AppData` из `types.ts`. Если в одном языковом файле
появится новое поле, а в другом — нет, TypeScript не даст собраться, пока вы
не поправите оба.

## Как добавить/поправить звук

Каждый звук в `initials` / `finals` (в `data.*.ts`) — объект:

```ts
{
  id: 'alveolar',
  pinyin: 'd · t · n · l',
  name: 'Альвеолярные',
  marker: { x: 133, y: 138 },   // где стоит янтарная точка контакта
  noContact: false,              // true → точка становится пунктирным кольцом (нет смыкания, как у -r)
  velum: true,                    // true → мягкое нёбо открывается (носовые звуки: -n, -ng)
  top: [                           // ровно 6 точек: [кончик, спинка, перед-спинки, середина, зад, корень]
    { x: 131, y: 143 }, { x: 172, y: 203 }, { x: 210, y: 249 },
    { x: 252, y: 272 }, { x: 296, y: 287 }, { x: 338, y: 298 }
  ],
  title: '...',
  body: '...',                     // можно <b>...</b>
  example: 'pīnyīn → 汉字 «перевод»'
}
```

Координаты — в системе SVG `viewBox="0 0 640 440"`. Если `top` не будет
содержать ровно 6 точек, TypeScript откажется собирать проект (тип `TongueTop`
— кортеж фиксированной длины). Проще всего скопировать координаты у похожего
по месту артикуляции звука, подвинуть на глаз и пересобрать (`npm run build`),
проверив в браузере — сборка занимает меньше секунды.

## Запуск локально

Нужен Node.js. Модули собираются как настоящие браузерные ES-модули
(`<script type="module">`), поэтому открыть страницу двойным кликом
(`file://`) не получится — браузеры блокируют модули по CORS для `file://`.
Нужен локальный сервер:

```bash
npm install
npm run build          # компилирует src/*.ts → dist/*.js
python3 -m http.server 8000
# затем откройте http://localhost:8000/ru.html
```

Во время правок удобно держать компилятор в режиме наблюдения:

```bash
npx tsc --watch
```

## Проверки (типы + линтеры)

```bash
npm run typecheck   # tsc --noEmit
npm run lint:ts      # ESLint по src/**/*.ts
npm run lint:html    # html-validate по *.html
npm run lint          # всё сразу
```

Тот же прогон автоматически запускается в GitHub Actions на каждый push
и pull request (`.github/workflows/lint.yml`).

## Тесты

Два слоя, оба реально гоняются в этом репозитории (не только описаны словами):

```bash
npm run build          # тестам нужен собранный dist/
npm run test:unit       # node --test — геометрия языка + согласованность данных ru/en
npx playwright install --with-deps chromium   # один раз, для e2e
npm run test:e2e         # Playwright — реальный браузер, оба языка, все 9 звуков
npm test                  # build + unit + e2e одной командой
```

**Юнит-тесты** (`tests/unit/`, без браузера):
- `geometry.test.mjs` — что `tongueD`/`velumD` строят корректный path; отдельно
  регрессионный тест на баг «толщина языка выворачивается в петлю» (был найден
  и исправлен при разработке — теперь закреплён тестом на нескольких реальных
  конфигурациях точек).
- `data.test.mjs` — что `data.ru.ts` и `data.en.ts` не расходятся по набору
  звуков, что `top` всегда ровно из 6 точек и в границах viewBox, и что
  доменные факты закреплены явно: `-n` совпадает по месту языка с `d/t/n/l`,
  `-ng` — с `g/k/h`, `-r` без контакта и без назализации, ни один инициаль не
  открывает нёбную занавеску.

**E2E-тесты** (`tests/e2e/app.spec.ts`, Playwright, реальный Chromium):
- страница грузится без ошибок в консоли — на обоих языках
- клик по каждой из 6 инициалей и 3 финалей ни разу не роняет JS-ошибку и
  всегда оставляет непустой path языка
- цвет языка идёт через CSS-класс `.tongue-shape`, а не инлайн-атрибут — это
  прямой регрессионный тест на баг с Safari из этого же чата
- `-n`/`-ng` включают пунктирную линию воздуха в нос, остальные звуки — нет
- подписи анатомии не перекрываются ни на одном из трёх размеров экрана
  (320/700/1080px) — автоматизация той самой проверки через `getBBox()`,
  которую раньше приходилось гонять руками

Тот же прогон (`build` → `test:unit` → установка браузера → `test:e2e`)
выполняется в GitHub Actions на каждый push/PR (`.github/workflows/test.yml`).
Деплой (`deploy.yml`) дополнительно гоняет `test:unit` как быстрый gate перед
публикацией (без e2e — чтобы не тормозить деплой установкой браузера).

## Деплой на GitHub Pages

Деплой полностью автоматический через `.github/workflows/deploy.yml`:
при каждом пуше в `main` workflow ставит зависимости, прогоняет typecheck,
собирает TypeScript (`npm run build`) и публикует статику через официальные
`actions/upload-pages-artifact` + `actions/deploy-pages`.

Разовая настройка:

1. Запушьте репозиторий в `main` на GitHub
2. Settings → Pages → Source → выбрать **GitHub Actions** (не «Deploy from a
   branch» — сборка теперь в CI, `dist/` в репозитории нет)
3. После первого прогона workflow сайт появится по адресу
   `https://<ваш-логин>.github.io/<репозиторий>/`
4. Эту ссылку можно смело кидать в Telegram и куда угодно — это настоящая
   веб-страница, а не файл, поэтому JS и интерактивность будут работать
   в мобильных браузерах (включая встроенный браузер Telegram).

## Известные особенности реализации

- Цвет и обводка языка заданы через CSS-класс `.tongue-shape`, а не через
  инлайн-атрибуты `fill="var(--tongue)"` — в части версий Safari
  CSS-переменные в presentation-атрибутах SVG не резолвятся, из-за этого
  язык мог не отрисовываться. Если добавляете новые SVG-элементы с цветом
  из палитры — красьте их так же через класс, а не атрибут.
- Подписи анатомии в SVG специально разнесены по двум ярусам (см.
  комментарий в `engine.ts`) — расстояния были проверены через `getBBox()`,
  чтобы текст не перекрывался ни на одном размере экрана. При добавлении
  новых подписей стоит проверить то же самое.
- Форма нижней границы языка в `geometry.ts` считается относительно верхних
  точек (`tip.y + 36` и т.д.), а не фиксированными координатами — это
  гарантирует, что толщина языка не «вывернется» в самопересекающуюся
  петлю при экстремальных положениях (проверено рендером на всех 9 звуках).
